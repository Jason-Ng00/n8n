# n8n Deploy Python Fix

## Project Requirement
Deploy n8n to Render using a custom Dockerfile to support executing Python nodes natively. Fix the "Virtual environment is missing from this system. Internal mode is intended only for debugging. For production, deploy in external mode" error that appears upon executing a Python node.

## Functionality
- Override or correctly configure the internal Python task runner environment path.
- Enable `N8N_RUNNERS_MODE=internal` for single-container execution.
- Maintain a seamless Render deployment script.

## Dev Logs - 2026-04-02
- Investigating the `venv` path that `n8n` task runner expects.
- **Update**: Discovered that `n8n` version `2.14.2` uses PNPM, meaning `task-runner-python` is buried within `.pnpm` strict node symlinks, rendering traditional folder discovery (`find`) unstable or inaccurate for the virtual environment hook point.
- **Solution (Venv Missing Error)**: Reworked the `Dockerfile` to build the `.venv` independently at a fixed absolute point (`/opt/venv`). Then, injected a post-installation hook that executes a python string substitution over n8n's compiled JS framework. This hook directly modifies the parsed `getVenvPath() { ... }` method structure inside the JS target file `task-runner-process-py.js` that evaluates the virtual environment logic. By forcing n8n's internal engine to return `"/opt/venv/bin/python"` exclusively, we permanently decouple the `.venv` from n8n's volatile internal module routing.
- **Update (Task Timeout Error)**: Follow-up testing triggered a 60-second Task Timeout error. This occurred because while the Python runner *spawned* successfully, the Node.js child process evaluated the `cwd` directory execution context using `__dirname` alongside PNPM's deep symlinks. Since `__dirname` returned the `.pnpm` nested source location, relative traversal (`../../../`) broke and pointed the python command at an empty folder instead of the python task runner's true installation. The runner immediately crashed and entered a silent reboot loop.
- **Solution (CWD Fix & Build Fix)**: Initially introduced a dynamic NodeJS expression (`require("path").dirname(require.resolve("@n8n/task-runner-python/package.json"))`) to evaluate the true absolute package directory, but this failed inside the minimal Docker image layer due to lack of `NODE_PATH` exposure during installation hooks. Reworked the execution to natively `find` the expected `src/main.py` entrypoint. The Python patch script slices this directory explicitly and safely overwrites the `pythonDir` variable natively inside `task-runner-process-py.js` so Python boots consistently inside the native N8N environment.
